## 2. Roles

Everybody writes code, everybody commits, and we review each other's work. Since this is a 3-member group, we have divided the coding and testing tasks equally among us:

- **Coordinator & Outputs (Member 1):** Handles GitHub setup, `results_to_csv`, `build_report`, named constants, README, and the final CLI run. Also acts as the main reviewer. 
- **Core Logic (Member 2):** Handles `classify_variant`, `triage`, and the boundary/invalid-input tests.
- **Summaries & Ranking (Member 3):** Handles `decision_counts`, `impact_counts`, `gene_summary`, `rank_variants`, and awkward-input tests.
- **All members:** Will collaborate on `docs/design.md` and the hand-trace table before coding, and will review each other's code.

We will rotate the "Reviewer" role for each major pull request so everyone practices reviewing code.


## 3. How we make decisions

We discuss tasks and problems and divide it equally in our WhatsApp group. For coding decisions, we try to reach a mutual agreement among all members. If there is a disagreement we put it to a vote using whatsapp poll. The Coordinator (Member 1) will determine the final verdict. All final decisions regarding the project will be written down and tracked in the GitHub repository.

## 4. Meetings and communication

We will hold a weekly meeting on Discord every weekend at night to check progress and integrate our code. Our primary chat channel is WhatsApp, and we aim to reply to messages within 24 hours.

## 5. Rules for Git and for code

- Every member works under their own name: `git config user.name` and `user.email` are set on every machine.
- Every member makes at least 3 commits of real work. Nobody commits for somebody else.
- Commit messages say what changed and why. Small commits are better than one big commit.
- **Branch and review rule:** For this project, to avoid conflicts and keep things simple, we will pull the latest `main` branch before starting any work. We will push directly to `main` for small changes, but for large features, we will notify the group in WhatsApp before pushing. No one edits the `data/` folder or `ruff.toml`.

## 6. If someone does not contribute

We will follow these steps if a member is not contributing:
1. A friendly reminder in the WhatsApp group after one week.
2. A private group talk to see if they are facing any difficulties.
3. If the issue persists, we will email the lecturer. We understand the lecturer will use the Git commit history and the individual Q&A to adjust marks accordingly.

Before submission, we will check each other's log entries to ensure it is complete and follows Level 1 AI rules. Every member is responsible for the whole submission, including AI use by others, and every member signs the log and this contract.
